# Medioo Web Rebuild — Wave 2 (contracts, copy, images) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. In this repo each PR below runs as its own Workflow pipeline (master plan Part E): one worktree, one branch, one PR, no merge inside the pipeline.

**Goal:** Give the Next.js screens of Wave 3 everything they read and send through Java: the paper's display model, sign-in, upload, status and delete as `/app/api` JSON; images that load from a stable same-origin URL with known dimensions; and copy, Bangla digits and dates generated from Java's own bundles and formatters, so that React renders and never derives.

**Architecture:** Every new route joins `AppApiRouter` behind `AppApiGuard` (session, CSRF, `{reason}` errors, `no-store`, the pattern-only access line). The display rules that the HTML pages hold today in `ValueRows` and `DocumentPages` move into `web.domain.PaperDisplay`. The HTML pages and the JSON then read one rule, and the unchanged HTML render tests are the proof that the move changed nothing. Every file that crosses from Java to `medioo-web` is generated by a Java test, committed, and byte-compared on every build: copy, calendar, golden vectors and MSW fixtures. Vitest reads only the committed files, so CI step order never matters.

**Tech Stack:**
- Spring Boot 3.4 WebFlux and R2DBC, Testcontainers (Postgres 17, MinIO), JUnit 5, AssertJ, Jackson.
- Next.js 15 / React 19 / TypeScript strict, Vitest, Playwright (Chromium).

## Global Constraints

The master plan's [Global Constraints](2026-10-21-medioo-nextjs-rebuild.md#global-constraints) apply **verbatim** to every task here. They are not restated except where a Wave 2 task leans on one. The repository rules in `CLAUDE.md` apply too. Wave-specific constraints, one line each:

- **Gradle runs only through the lock.** Below, `gl <args>` means:
  ```
  PGHOST=localhost PGPORT=5433 PGDATABASE=medscribe PGUSER=medscribe PGPASSWORD=medscribe PGSCHEMA=medscribe LLM_PROVIDER=groq GROQ_API_KEY=ci-placeholder bash ~/medioo-design/tools/gradle-locked.sh <args>
  ```
  Run `gl build` before pushing any PR that touches Java.
- **Web commands** are `pnpm -C medioo-web <script>`. Before pushing any PR that touches `medioo-web`, run `pnpm -C medioo-web lint`, `typecheck`, `test` and `build`.
- **Migrations:** V22 belongs to Phase 0 PR 8 and V23 to PR 9. D4b's migration is written only after both are on `origin/main`. It takes the next free `V<n>` at that moment, and is renumbered on rebase if main moved. Never edit an applied migration.
- **Additive API only (A2).** A name in `ApiReason` keeps its meaning and its status forever. A JSON field, once shipped, is never renamed or retyped.
- **`docs/infra/app-routes.txt` is regenerated, never hand-merged.** A PR may only add lines under `/app/api/`. The PR body states this, for the PO's sign-off: `git diff origin/main -- docs/infra/app-routes.txt | grep '^-[A-Z*]'` must print nothing.
- **`AppApiLogSafetyTest` derives the list of `/app/api` routes from the routers.** Every new route must get an entry in its `exercise` map, or that test fails. This is intended.
- **Errors carry a name and nothing else.** The body is `{"reason":"<NAME>"}`. Numbers a refusal's copy needs (caps, attempts, dates) come from a GET the client already made. Never from the error body, never as prose.
- **No Bangla literal in `medioo-web` outside generated files.** From W2b on, a generated file is JSON whose `_meta.generated_by` names an existing Java test. Fixtures use only fictional data: names such as "রোকেয়া পরীক্ষা" or "Ma", numbers `+8801700000xxx`.
- **Logs never carry patient text, phone numbers, OTP codes, filenames or wamids above DEBUG.**
- **Commits** are conventional and end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Stage explicit paths only, never `git add -A` or `git add .`. PRs are opened with `env -u GITHUB_TOKEN gh pr create --base main`, and the PR body ends with `🤖 Generated with [Claude Code](https://claude.com/claude-code)`. **Never merge.**
- **Red replays (A8).** Each named guard is replayed against a deliberately broken build:
  - make the mutation, run the guard, and read the failure message;
  - confirm the message names the defect (an NPE, or a compile error in the test, is not a replay);
  - restore with `git checkout -- <file>`;
  - quote the failure line in the PR body.

## Review Focus

These are inputs no task's main tests exercise, but which are likely to reach a family. Each one has a test added to the task that owns the code.

1. **A legacy row from before DR-12 or V19.** It may have no `crop_key`, no `verdict`, or no observation `id`. The HTML page throws on a row without a crop, and the whole paper becomes a 500. Expected from the API: 200. The row is left out of `values`, and `unverified.values` counts it, which is what DR-28 says a value read but not located on the page is. A row with no verdict is `unknown`, never an error. Owner: B2, tests `aLegacyRowWithoutACropIsLeftOutAndCountedUnverified` and `aRowWithNoStoredVerdictIsUnknownNotAnError`.
2. **An undated paper sent after midnight in Dhaka.** It is dated by the Dhaka day, not the UTC day. For example, a paper received at `2026-10-20T18:30:00Z` is dated 21 October. Owner: B2, test `anUndatedPaperSentAfterDhakaMidnightIsDatedByTheDhakaDay`.
3. **An iPhone photo whose filename names the patient.** For example `রোকেয়া পরীক্ষা.jpg`, sent through the JSON upload. The filename appears in no log field at INFO or above, and in no response. Owner: B4b, as a needle in the `AppApiLogSafetyTest` exercise for `POST /app/api/uploads`.
4. **A paper deleted while it is still being read.** The pipeline must not leave crops, rows or objects behind for an id that no longer exists. Owner: B4c, test `aPaperDeletedWhileItIsBeingReadLeavesNothingBehind`. If it cannot pass, the fix refuses the delete with 409 `STILL_READING` while the paper is RECEIVED or PROCESSING, and the PR body says so.
5. **A viewer whose `baymax_lang=en`.** They get `?text=code` in the WhatsApp link, not `কোড`. Every `*_key` the JSON names resolves in both languages. Owner: B4a, test `theWaLinkIsTheCodePagesOwnLinkInTheViewersLanguage`. B2's contract tests also assert that each emitted key resolves in both bundles.

- **Mechanism (the first of B4b or B4c to land adds it).** `ApiReason.of(Throwable)` first looks up a `BaymaxException`'s `reason()` in `static final Map<String, ApiReason> BY_REASON`, and falls back to the existing by-status mapping.
- **Why the code refusals are 400, not 401.** 401 is reserved for "no session". The client's rule "401 → go to sign-in, keep `next=`" (master Review Focus 4) must never fire on a wrong code typed on the sign-in page itself.

  - `public static String page(UUID documentId, int pageNo)`.
- **History:**
  - B2 introduces the class, returning today's URLs (`/app/documents/{id}/image?key=…` and `/app/documents/{id}/page/{n}`). `PageChrome.imageHref` delegates to it.
  - D4a changes its output in that one place.
  - If D4a is ready first, D4a introduces the class with this signature, and B2 rebases onto it.

**Snapshot helper.** File: `baymax/src/test/java/com/elioo/baymax/testsupport/Snapshot.java`. It is added by the first PR that needs it (B2 or W2b).
- **Signature:** `public static void matches(Path committed, Path written, String content, String regenerate)`.
- **Behaviour:** it writes `content` to `written` (creating directories), asserts that `committed` exists, and asserts that the two are equal. The failure message is `regenerate` plus the path that was written. `regenerate` is a ready-to-run `cp` command.
- Tests run with the working directory at `baymax/`, so a committed path looks like `../medioo-web/...`.

**Generated-file envelope.** Every JSON file that Java writes for `medioo-web` has a top-level `"_meta": {"generated_by": "baymax <TestClass>", "source": "<what it was read from>"}`.
- **MSW fixtures** have the shape `{"_meta":…, "status": <int>, "body": <the exact response body>}`. MSW serves `body` with `status`, and never serves `_meta`.
- **Keys** are sorted. Files are written with two-space indent and end with a trailing newline, so a byte comparison is stable.

**PR-order hotspots.** The lane B PRs all touch these files: `AppApiRouter.mediooAppApiRoutes` (one route line and one parameter per PR), `ApiReason`, `docs/infra/app-routes.txt`, `AppApiLogSafetyTest`, and `AppApiGuardTest`'s constructor call `new AppApiRouter().mediooAppApiRoutes(...)`.
- Rebase onto a fresh `origin/main` before opening the PR.
- Regenerate the route snapshot, and re-add only your own lines everywhere else.
