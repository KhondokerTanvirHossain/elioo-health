# Medioo Web Rebuild — Wave 2 (contracts, copy, images) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. In this repo each PR below runs as its own Workflow pipeline (master plan Part E): one worktree, one branch, one PR, no merge inside the pipeline.

**Goal:** Give the Next.js screens of Wave 3 everything they read and send through Java: the paper's display model, sign-in, upload, status and delete as `/app/api` JSON; images that load from a stable same-origin URL with known dimensions; and copy, Bangla digits and dates generated from Java's own bundles and formatters, so that React renders and never derives.

**Architecture:** Every new route joins `AppApiRouter` behind `AppApiGuard` (session, CSRF, `{reason}` errors, `no-store`, the pattern-only access line). The display rules that the HTML pages hold today in `ValueRows` and `DocumentPages` move into `web.domain.PaperDisplay`. The HTML pages and the JSON then read one rule, and the unchanged HTML render tests are the proof that the move changed nothing. Every file that crosses from Java to `medioo-web` is generated by a Java test, committed, and byte-compared on every build: copy, calendar, golden vectors and MSW fixtures. Vitest reads only the committed files, so CI step order never matters.

**Tech Stack:**
- Spring Boot 3.4 WebFlux and R2DBC, Testcontainers (Postgres 17, MinIO), JUnit 5, AssertJ, Jackson.
- Next.js 15 / React 19 / TypeScript strict, Vitest, Playwright (Chromium).

## Global Constraints

The master plan's [Global Constraints](2026-10-21-medioo-nextjs-rebuild.md#global-constraints) apply **verbatim** to every task here. They are not restated except where a Wave 2 task leans on one. The repository rules in `CLAUDE.md` apply too. Wave-specific constraints, one line each:

- **Gradle runs only through the lock.** Below, `gl <args>` means:
  ```
  PGHOST=localhost PGPORT=5433 PGDATABASE=medscribe PGUSER=medscribe PGPASSWORD=medscribe PGSCHEMA=medscribe LLM_PROVIDER=groq GROQ_API_KEY=ci-placeholder bash ~/medioo-design/tools/gradle-locked.sh <args>
  ```
  Run `gl build` before pushing any PR that touches Java.
  - **What the lock is for.** Parallel worktrees share the Docker Postgres on `localhost:5433`. Two Gradle runs at once run Flyway and the context tests against the same schema and fail each other. The script takes a machine-wide `mkdir` lock and then runs `./gradlew <args>`; nothing else.
  - **Fallback.** Where the script does not exist (a fresh machine, a cloud agent, CI), run `./gradlew <args>` with the same environment variables, and make sure no other Gradle run uses the same Postgres at the same time. CI already runs one build per job against its own Postgres service.
  - The script is a local tool and is not in the repo; this PR does not add it (it is macOS-specific: `stat -f`).
- **Web commands** are `pnpm -C medioo-web <script>`. Before pushing any PR that touches `medioo-web`, run `pnpm -C medioo-web lint`, `typecheck`, `test` and `build`.
- **Migrations:** V22 belongs to Phase 0 PR 8 and V23 to PR 9. D4b's migration is written only after both are on `origin/main`. It takes the next free `V<n>` at that moment, and is renumbered on rebase if main moved. Never edit an applied migration.
- **Additive API only (A2).** A name in `ApiReason` keeps its meaning and its status forever. A JSON field, once shipped, is never renamed or retyped.
- **`docs/infra/app-routes.txt` is regenerated, never hand-merged.** A PR may only add lines under `/app/api/`. The PR body states this, for the PO's sign-off: `git diff origin/main -- docs/infra/app-routes.txt | grep '^-[A-Z*]'` must print nothing.
- **`AppApiLogSafetyTest` derives the list of `/app/api` routes from the routers.** Every new route must get an entry in its `exercise` map, or that test fails. This is intended.
- **Errors carry a name and nothing else.** The body is `{"reason":"<NAME>"}`. Numbers a refusal's copy needs (caps, attempts, dates) come from a GET the client already made. Never from the error body, never as prose.
- **No Bangla literal in `medioo-web` outside generated files.** From W2b on, a generated file is JSON whose `_meta.generated_by` names an existing Java test. Fixtures use only fictional data: names such as "রোকেয়া পরীক্ষা" or "Ma", numbers `+8801700000xxx`.
- **Logs never carry patient text, phone numbers, OTP codes, filenames or wamids above DEBUG.**
- **Commits** are conventional and end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Every commit command below passes it as a second `-m`. Stage explicit **file** paths only: never `git add -A`, `git add .`, or a directory. Before each commit, run `git status --short -- baymax/src medioo-web docs` and check that it shows nothing outside the staged list. A file a step changed but the list left out builds locally and fails in CI. PRs are opened with `env -u GITHUB_TOKEN gh pr create --base main`, and the PR body ends with `🤖 Generated with [Claude Code](https://claude.com/claude-code)`. **Never merge.**
- **Red replays (A8).** Each named guard is replayed against a deliberately broken build:
  - make the mutation, run the guard, and read the failure message;
  - confirm the message names the defect (an NPE, or a compile error in the test, is not a replay);
  - restore with `git checkout -- <file>`;
  - quote the failure line in the PR body.
  - A test written after the code it guards (because an earlier step already made it pass) is not done until it has its own replay.
- **Box access** is read-only, and only for the steps that say so: `ssh ec2-user@<the host in CLAUDE.md, Environment facts> '<command>'`, with the operator's own key. This repo is public (DR-38), so no key file or path is written here.

## Review Focus

These are inputs no task's main tests exercise, but which are likely to reach a family. Each one has a test added to the task that owns the code.

1. **A legacy row, in the shapes Postgres can actually hold.** `observation`, `medication_event` and `follow_up` have had `crop_key text NOT NULL` since V5 ("no number without its source crop"), so a stored value without a crop cannot exist. The `unverified_*` counts (V6) count items dropped at extraction, never stored rows. The legacy shapes that do exist are:
   - a value with no stored `verdict` (written before V19). It is `unknown`, never an error;
   - a `clinical_context` line with no `crop_key`. It is left out of `doctor`, exactly as `DocumentPages.contextQuotes` skips it today.

   A value row whose `crop_key` is blank anyway (a mock, or a future column change) is skipped defensively. That skip changes neither `unverified` nor `counts`, because `counts` is computed by the same `PaperDisplay` call over the same list the HTML counts line reads. Owner: B2, tests `aRowWithNoStoredVerdictIsUnknownNotAnError`, `aContextLineWithoutACropIsLeftOutAsTheHtmlLeavesItOut` and `theJsonCountsAreTheHtmlCountsLine`.
2. **An undated paper sent after midnight in Dhaka.** It is dated by the Dhaka day, not the UTC day. For example, a paper received at `2026-10-20T18:30:00Z` is dated 21 October. The other direction: a paper whose printed date is not ISO (`12/10/2026`) is shown as printed, never as the upload day. Owner: B2, tests `anUndatedPaperSentAfterDhakaMidnightIsDatedByTheDhakaDay` and `aPrintedDateThatIsNotIsoIsShownAsPrintedNeverAsTheUploadDay`.
3. **An iPhone photo whose filename names the patient.** For example `রোকেয়া পরীক্ষা.jpg`, sent through the JSON upload. The filename appears in no log field at INFO or above, and in no response. Owner: B4b, as a needle in the `AppApiLogSafetyTest` exercise for `POST /app/api/uploads`. That exercise must reach the **success** path (200), which needs real object storage in the log-safety context (B4b Step 10).
4. **A paper deleted while it is still being read.** The pipeline must not leave crops, rows or objects behind for an id that no longer exists, and must not compose or deliver an explanation of it. Owner: B4c, test `aPaperDeletedWhileItIsBeingReadLeavesNothingBehind`. If it cannot pass, the fix refuses the delete with 409 `STILL_READING` while the paper is RECEIVED or PROCESSING, and the PR body says so.
5. **A viewer whose `baymax_lang=en`.** They get `?text=code` in the WhatsApp link, not `কোড`, and English possessives ("Ma's"), not a Bangla case ending. Every `*_key` the JSON names resolves in the set React will read: `UiCopy.keys(lang)` together with the `urgency.*` keys of `messages_<lang>.properties`, the same union W2b exports. Owner: B4a, test `theWaLinkIsTheCodePagesOwnLinkInTheViewersLanguage`; B2, tests `everyEmittedKeyResolvesInBothLanguages` and `theNameIsDeclinedInTheViewersLanguage`.
